# Contributing

## Where to start

[stead.ing](https://stead.ing/), with a landing page for each project, and the docs at `docs.stead.ing` are Steading's front doors; [hosting](hosting.md#where-things-live) says where everything lives.[^hosting] This wiki is the source of truth behind them, for people and agents alike.[^governance]

Join the discussion on [Discord](https://discord.gg/BjCu2vHgX4).[^governance]

## Finding work

The backlog is the GitHub issues and pull requests in each [repository](repositories.md).[^governance] The next goal is for [skift](skift.md#steading-ais-tracker) to be the tracker, starting with maintainers and their agents.[^hosting]

Before spending tokens on a contribution, start with an issue, or a discussion on Discord.[^governance]

## Sending work

Agent-written pull requests are preferred.[^governance] Any maintainer can merge one: see [governance](governance.md#merging).

## Licensing

Steading's projects are under the ISC license. There's no CLA, sign-off, or code of conduct; the project isn't big enough to need one.[^governance]

## Security

Report a vulnerability to the repository it affects: follow its `SECURITY.md`, or report it privately through GitHub's [private vulnerability reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability).[^governance]
